ElementsKit has two layers for building UI: **elements** (DOM nodes created with JSX) and **components** (classes that produce elements). Both are standard web platform — no virtual DOM, no framework runtime.

---

## Elements and JSX

JSX in ElementsKit compiles directly to `document.createElement` calls. There is no virtual DOM or diffing layer — every JSX expression produces a real DOM node immediately.

```tsx
// This JSX:
const el = <button onClick={() => count(count() + 1)}>Click me</button>;

// Is equivalent to:
const el = document.createElement("button");
el.addEventListener("click", () => count(count() + 1));
el.append("Click me");
```

Configure your `tsconfig.json` once and JSX just works:

```json
{
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "elements-kit"
  }
}
```

### Live bindings

Passing a signal or a `() => T` function as a child or prop creates a **live binding** — the DOM node updates in place whenever the value changes, with no re-render of the surrounding tree.

```tsx
const count = signal(0);

// Both create a live text node that updates when count changes
<p>Count: {count}</p>
<p>Count: {() => count()}</p>

// Reactive props
<input value={count} on:input={(e) => count(e.target.value)} />

// Conditional element — replaces the node when show changes
<div>{() => show() && <strong>Visible</strong>}</div>
```

### Prop namespaces

| Syntax | Effect |
|--------|--------|
| `{signal}` / `{() => fn()}` | Live-bound reactive child |
| `onClick={fn}` | Event listener (camelCase maps to `onclick`) |
| `on:click={fn}` | Explicit event namespace |
| `class:active={bool}` | Reactive `classList.toggle` |
| `style:color={value}` | Reactive inline style property |
| `prop:foo={val}` | Force property assignment (skips `setAttribute`) |

## Class Components

A **component** is a class with a `render()` method that returns an `Element`. It can hold reactive state, computed values, and event handlers — all in one place.

```tsx
import { signal, computed } from "elements-kit/signals";

class Counter {
  // State
  #count = signal(0);
  doubled = computed(() => this.#count() * 2);

  // View
  render() {
    return (
      <section>
        <p>Count: <strong>{this.#count}</strong> — Doubled: <strong>{this.doubled}</strong></p>
        <button onClick={() => this.#count(this.#count() + 1)}>+1</button>{" "}
        <button onClick={() => this.#count(0)}>Reset</button>
      </section>
    ) as Element;
  }
}

document.getElementById("app")!.appendChild(new Counter().render());
```

### Store + render

When state needs to be **shared** across components, split it into a dedicated **store** — a class with `@reactive` fields and no `render()`. Components then read from the store.

```tsx
import { reactive, computed } from "elements-kit/signals";

// Store — reactive state, no DOM
export class CounterStore {
  @reactive() count = 0;
  doubled = computed(() => this.count * 2);

  increment() { this.count++; }
  reset()     { this.count = 0; }
}

export const counter = new CounterStore();
```

```tsx
// Component — reads from the store, renders elements
class CounterDisplay {
  render() {
    return (
      <p>
        {() => counter.count} × 2 = {counter.doubled}
      </p>
    ) as Element;
  }
}

class CounterControls {
  render() {
    return (
      <div>
        <button onClick={() => counter.increment()}>+1</button>
        <button onClick={() => counter.reset()}>Reset</button>
      </div>
    ) as Element;
  }
}
```

The store is framework-agnostic — you can read from it in a custom element, a React component, or a plain effect — all sharing the same reactive state.

## Custom Elements

Custom elements are native browser components — a class that extends `HTMLElement` and registers under a tag name. ElementsKit enhances them gradually; you start with the platform and add only what you need.

### Step 1 — Bare custom element

The browser's built-in API, no dependencies:

```ts
class CounterElement extends HTMLElement {
  #count = 0;

  connectedCallback() {
    // Manual DOM construction and update
    this.innerHTML = `
      <p>Count: <strong id="val">0</strong></p>
      <button>+1</button>
    `;
    this.querySelector("button")!.addEventListener("click", () => {
      this.#count++;
      this.querySelector("#val")!.textContent = String(this.#count);
    });
  }
}

customElements.define("x-counter", CounterElement);
```

It works, but every state change requires manual DOM queries and text updates. Adding more state means more bookkeeping.

## `For` — Keyed list rendering

`For` efficiently reconciles a reactive array into the DOM. Each item is rendered **once** per unique key — no full re-renders on reorder, add, or remove.

```tsx
import { For } from "elements-kit";

<ul>
  <For each={todos} by={(todo) => todo.id}>
    {(todo) => (
      <li style:text-decoration={computed(() => todo.done ? "line-through" : "none")}>
        <input
          type="checkbox"
          checked={computed(() => todo.done)}
          on:change={() => (todo.done = !todo.done)}
        />{" "}
        {todo.text}
      </li>
    )}
  </For>
</ul>
```

| Prop | Type | Description |
|------|------|-------------|
| `each` | `T[] \| (() => T[])` | Reactive array to render |
| `by` | `(item: T, index: number) => string \| number` | Key function — defaults to index |
| `children` | `(item: T, index: number) => Element` | Render function, called once per new key |
