One frame, orthogonal primitives. `.x-overlay` wraps a [Card](/ui/card) in a native `<dialog>` or [popover](https://developer.mozilla.org/en-US/docs/Web/API/Popover_API) and owns positioning, the top layer, enter/exit animation, detent sizes, and the backdrop — the platform owns focus trapping, Esc, light dismiss, and focus return. Zero JS required; gestures are an opt-in module.

- **Location** — `--overlay-x` / `--overlay-y`, a point inside the constraint rect (unset = centered; saturated values dock flush to the edges).
- **Size** — `--overlay-w` / `--overlay-h`, explicit channels (unset = detent / `--overlay-max-width` × fit-content).
- **Resize** — `data-resize`, the side the resize handle sits on; a `start`/`end` pair for a corner grip.
- **Draggable** — `data-draggable`, the x/y move gesture.
- **Modality** — how you open it, no attribute needed.
- **Anchor** — `data-anchor` is *reserved* for future element anchoring (CSS Anchor Positioning); v1 anchors to the constraint rect only.

## Location, resize, draggable

`--overlay-x` / `--overlay-y` are lengths from the constraint rect's top-left corner to the overlay's **center**. Unset, the overlay is centered. The stylesheet clamps the point so the box can never leave the rect — which makes saturated values a vocabulary: `--overlay-y: 9999px` *is* "the bottom edge", reactively, whatever the rect or the box size becomes.

`data-resize` names the side the resize handle sits on (the opposite side stays anchored): the four edge words `block-start`, `block-end`, `inline-start`, `inline-end` — or a single corner word, a `start`/`end` pair with the **block side first**: `start-start`, `start-end`, `end-start`, `end-end` (e.g. `end-end` = block-end + inline-end, the bottom-right grip). The handle side picks the detent axis, the gesture, the affordance, and the enter/exit slide. No attribute, no resize.

`data-draggable` (boolean) adds the x/y move gesture from the top strip.

The classic shapes are compositions:

| Recipe | Channels | Attributes |
| --- | --- | --- |
| Bottom sheet | `--overlay-y: 9999px; --overlay-w: var(--overlay-constraint-width)` | `data-resize="block-start"` + `data-detent` |
| Top sheet | `--overlay-y: -9999px; --overlay-w: var(--overlay-constraint-width)` | `data-resize="block-end"` |
| Right drawer | `--overlay-x: 9999px; --overlay-h: var(--overlay-constraint-height)` | `data-resize="inline-start"` |
| Centered window | *(defaults)* | `data-resize="end-end"` + `data-draggable` |
| Corner panel | `--overlay-x: 9999px; --overlay-y: 9999px` | `data-resize="block-start"` |

Everything is expressed in interpolable lengths — changing the location point, the size channels, or `data-detent` on an *open* overlay morphs it with a plain CSS transition. That's the whole Apple-Maps trick: a persistent `popover="manual"` panel that glides between corner, sheet, and centered while the page stays interactive.

`data-resize` words are logical — gestures and affordances mirror in RTL. The location point is **physical**: RTL apps that want mirrored docking mirror `--overlay-x` themselves.

## Constraint

Every location clamp, detent, and size cap derives from one **constraint rect**:

```css
--overlay-constraint-top: 0px;
--overlay-constraint-left: 0px;
--overlay-constraint-width: 100vw;   /* 100svw where supported */
--overlay-constraint-height: 100vh;  /* 100svh where supported */
```

The location point clamps inside the rect, detents are fractions of it (`medium` = 60% of the constraint height), and the gesture bounds *are* it. All of the geometry is computed in the cascade (`calc`/`min`/`clamp` against these variables), so it re-clamps reactively when the viewport — or the rect — changes, with no JS running.

To confine an overlay to a container instead of the viewport, write `px` values into the variables, or use the opt-in helper:

```ts
import { constrainOverlay } from "elements-kit/ui/overlay/constrain";

constrainOverlay(overlay, document.querySelector("main")!);
```

It observes the container with a `ResizeObserver` (via `createElementRect`) and syncs its rect into the variables — docked overlays pin to the container's edges, the window moves and resizes only within it. Disposal (scope `onCleanup`, `dispose()`, or `Symbol.dispose`) removes the variables, restoring the viewport constraint. Caveat: a container that *moves* without resizing (page scroll) doesn't retrigger the sync.

## Modality

Modality is *how you open it* — same markup, no attribute:

```html
<!-- Modal: backdrop, focus trap, inert page -->
<dialog class="unset x-overlay" id="filters" data-resize="block-start" data-detent="medium"
        style="--overlay-y: 9999px; --overlay-w: var(--overlay-constraint-width)">
  <div class="x-card" data-variant="elevated" data-size="3">…</div>
</dialog>
<button onclick="document.getElementById('filters').showModal()">Filters</button>

<!-- Non-modal: top layer, light dismiss, page interactive -->
<dialog class="unset x-overlay" id="info" popover>
  <div class="x-card" data-variant="elevated">…</div>
</dialog>
<button popovertarget="info">Info</button>

<!-- Persistent: top layer, no light dismiss, page interactive (Apple Maps) -->
<dialog class="unset x-overlay" id="panel" popover="manual"
        data-resize="block-start" data-detent="small"
        style="--overlay-x: 9999px; --overlay-y: 9999px">
  <div class="x-card" data-variant="elevated" data-size="2">…</div>
</dialog>
<button popovertarget="panel">Toggle panel</button>
```

Markup contract: the frame's required direct child is a `.x-card` — that card is the visible surface, any variant and size. The frame paints nothing itself except the gesture affordances, so the card's own pseudo-element surface and ring are untouched.

## API

| Attribute *(on the frame)* | Values |
| --- | --- |
| `data-resize` | handle side: edges `block-start`, `block-end`, `inline-start`, `inline-end`; corners are a `start`/`end` pair, block side first (`start-start`, `start-end`, `end-start`, `end-end`); no default |
| `data-draggable` | boolean — x/y move gesture from the top strip |
| `data-detent` | `small`, `medium`, `large` — steps the resize axis: heights for block handles, widths for inline handles and corner grips |
| `data-anchor` | **reserved** for future element anchoring — do not use |
| `data-overlay-gestures` | written by `createOverlayGestures` while attached; gates the affordances (set it by hand if you wire your own dragging) |
| `data-material-background` | the card surface defaults to **solid** inside an overlay when no material context is declared (translucent over the dimmed backdrop reads as the backdrop covering the card); an explicit `solid`/`translucent` on the frame or any ancestor wins |

| Custom property | Default | Role |
| --- | --- | --- |
| `--overlay-constraint-top/-left/-width/-height` | the viewport | the [constraint rect](#constraint) all geometry derives from |
| `--overlay-x` / `--overlay-y` | rect center | the location point — rect-relative lengths to the box center, clamped by CSS; the move gesture persists the released spot here |
| `--overlay-w` / `--overlay-h` | detent / `--overlay-max-width` × fit-content | size channels; the corner resize gesture persists here |
| `--overlay-duration` | `300ms` | transition duration |
| `--overlay-easing` | iOS-style ease-out | transition easing |
| `--overlay-max-width` | `480px` | default width cap |
| `--overlay-detent-small/-medium/-large` | block heights `25svh` / `60svh` / `100svh − --space-9`; inline widths `280px` / `480px` / `100svw − --space-9`; corner widths `320px` / `--overlay-max-width` / `100svw` | detent sizes per resize axis |
| `--overlay-backdrop` | `--color-overlay` | backdrop color (modal only) |

## Detents & gestures

CSS owns the detent *positions*: `data-detent` picks a size from the `--overlay-detent-*` knobs along the `data-resize` axis, and flipping the attribute animates between them. The opt-in JS module adds what CSS can't, dispatched by the gesture attributes:

- **Single `data-resize` word** — whole-surface drag between detents along that axis (heights for block handles, widths for inline handles), RTL-aware, flick-to-dismiss past the smallest.
- **Corner word (`start`/`end` pair)** — desktop-window resize from a square zone at that corner; the opposite corner stays anchored, so the grip tracks the pointer 1:1 and the surface never outgrows the constraint. Free-form by default (the size persists via `--overlay-w/-h`, the location point shifts by half the growth to pin the anchor); pass a `detents` option and the release snaps to the width steps instead. Shrinking far past the minimum dismisses.
- **`data-draggable`** — **moves** the surface in x/y from the top strip, constrained to the rect with rubber-band resistance at the edges; the released spot persists via `--overlay-x/-y`, and flinging the surface off the constraint — any side — closes it (a slow over-drag springs back).

```ts
import { createOverlayGestures } from "elements-kit/ui/overlay";

const overlay = document.querySelector<HTMLDialogElement>("#filters")!;
const gestures = createOverlayGestures(overlay, {
  detents: ["small", "medium", "large"], // default; on corner grips: switches resize to snapping
  dismissible: true,                     // drag/flick past smallest closes
  velocityThreshold: 0.5,                // px/ms
});

overlay.addEventListener("detentchange", () => console.log(gestures.detent));
gestures.setDetent("large"); // programmatic, animated by CSS
gestures.dispose();          // or rely on an enclosing effectScope
```

While dragging, the module drives the overlay's size inline with transitions suppressed and text selection disabled; on release it snaps to the nearest detent — biased by flick velocity — by writing `data-detent` back, so CSS owns every resting state. Dragging past the largest detent rubber-bands; dragging or flicking past the smallest closes the overlay (`close()` for dialogs, `hidePopover()` otherwise). Dismissing restores the channel values the author had set when the gestures attached, so a closed overlay reopens fresh. Drags never start from interactive elements (buttons, links, inputs), so the card's content keeps working.

While attached, the factory sets `data-overlay-gestures` on the frame — that's what shows the grabber pills and the corner grip. No gestures, no affordance.

Inside an `effect` / `effectScope`, cleanup is automatic via `onCleanup`; standalone, call `dispose()` (also exposed as `Symbol.dispose` for `using`).

## Deck effect

Opt-in recipe: put `data-overlay-deck` on your page wrapper and it scales back iOS-style while a bottom sheet (`data-resize="block-start"`) is open — pure CSS via `:has()`, degrades to nothing.

```html
<body>
  <div data-overlay-deck><!-- page --></div>
  <dialog class="unset x-overlay" data-resize="block-start"
          style="--overlay-y: 9999px; --overlay-w: var(--overlay-constraint-width)">…</dialog>
</body>
```

## How the tiers work

Mirroring the [Segmented Control](/ui/segmented-control)'s approach, every modern feature is fenced behind `@supports`:

- **Tier 1 — universal.** Native `<dialog>` opens/closes instantly; location, size, and detent *morphs* animate wherever the `translate` property exists (Chrome 104+, Safari/Firefox at the floor). Focus trap, `::backdrop`, Esc — all platform behavior.
- **Tier 2 — enter/exit.** `@supports (transition-behavior: allow-discrete)` adds enter/exit transitions with [`@starting-style`](https://developer.mozilla.org/en-US/docs/Web/CSS/@starting-style): single-handle overlays slide from the edge their handle implies (a `block-start` handle means the sheet rests at the bottom — it slides from below), windows (no handle, or a corner grip) fade and settle, the backdrop fades.
- **Tier 3 — top-layer exit.** A nested `@supports (overlay: auto)` keeps the *exit* transition inside the top layer. Firefox currently clips the exit; entry is unaffected.
- **Size morphs.** `@supports (interpolate-size: allow-keywords)` lets `fit-content` heights interpolate during morphs; elsewhere size snaps while position slides.
- **Popover modality.** The `popover` attribute needs Chrome 114 / Safari 17 / Firefox 125 — above the library floor, so on older browsers a popover overlay stays hidden rather than rendering broken.

## Accessibility

The platform does the heavy lifting — don't re-implement it:

1. **Label the dialog.** `aria-labelledby` pointing at the card's heading (or `aria-label` on the frame).
2. **`showModal()`, not `show()`.** Modal overlays rely on it for the top layer, focus trap, inert background, and `::backdrop`.
3. **Focus return is free.** Closing a modal dialog or popover returns focus to the invoker natively.
4. **Esc is free.** `<dialog>` fires `cancel` then `close`; popovers light-dismiss. Don't intercept Esc.
5. **Affordances are decorative.** Grabbers and the resize grip are pseudo-elements, invisible to AT. Always provide a visible close button inside the card — gestures are pointer-only.
6. **Reduced motion.** `prefers-reduced-motion: reduce` removes every transition.
7. **Forced colors.** Affordances get `ButtonText` fallbacks.

APG pattern: [WAI-ARIA Authoring Practices — Dialog (Modal)](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).

:::caution[Don't]
Put the overlay's only close affordance behind a gesture. Gestures are an enhancement; Esc, backdrop click, and a visible button are the baseline.
:::

:::caution[Don't]
Use the popover modality for content that must block interaction — that's a job for `showModal()`. Popovers are non-modal by design.
:::

## When not to use

- **Menus, selects, tooltips** — purpose-built patterns with their own keyboard models; the popover modality is for rich non-modal surfaces, not lists of actions.
- **Full-page takeovers** — navigate instead; an overlay implies the page underneath stays relevant.

## Browser support

- **Tier 1** — every browser at `elements-kit`'s build targets (Chrome / Firefox 100+, Safari 16+): fully functional dialogs. Location morphs need the `translate` property (Chrome 104+); Chrome 100–103 gets a centered static fallback (saturated location points are not honored there).
- **Tier 2/3 animations** — Chrome 117+, Safari 17.4+, Firefox 129+ (`allow-discrete` + `@starting-style`); `overlay` in Chrome 117+ / Safari 26+.
- **Popover modality** — Chrome 114+, Safari 17+, Firefox 125+. Hidden (never broken) below that.
- **Size morphs** — `interpolate-size` (Chrome 129+); position still glides elsewhere.
- **Gestures (JS)** — Pointer Events, everywhere at the floor. `:dir()`-aware via `getComputedStyle`.
