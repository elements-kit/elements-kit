title: Async Utility
---


The `async` utility in ElementsKit provides a reactive, signal-based wrapper for asynchronous operations. It enables you to manage loading, error, and result states in a fine-grained, composable way.

## Basic Usage

```ts
import { async, Async } from "elements-kit/utilities/async";

const promise = async(() => fetch("/api/items"));
```

## Using Parameters

You can define an async operation that takes an input parameter. The input type is inferred from your function signature:

```ts
import { signal, effect } from "elements-kit/signals";

const todoId = signal(1);

const fetchTodo = async((id: number) => {
  return fetch(`https://jsonplaceholder.typicode.com/todos/${id}`)
    .then(res => {
        if (!res.ok) throw new Error("Not OK");
        return res.json();
    })
});

effect(() => {
  fetchTodo.run(todoId()); // re-fetches when todoId changes
});
```

You can use a signal as the input to your async operation and trigger reruns automatically:

```ts
import { async, Async } from "elements-kit/utilities/async";
import { signal, effect } from "elements-kit/signals";

const id = signal(1);

const fetchTodo = async(() => {
  return fetch(`https://jsonplaceholder.typicode.com/todos/${id()}`)
    .then(res => {
        if (!res.ok) throw new Error("Not OK");
        return res.json();
    })
});

fetchTodo.run()
```

## Error Handling: Throw or Assign

You can either throw an error or assign it to `this.error`:

```ts
const promise = async(function (this: Async) {
    return fetch(...)
        .then(res => {
            this.error = new Error("Network error"); // assign
            throw new Error("Network error");        // or throw
            return res.json();
        })
});
```

## Cleaning Error on Success / Data on Error

```ts
const promise = async(function (this: Async) {
    return fetch(...)
        .then(res => {
            const res = await fetch(...);
            if (!res.ok) throw new Error("fail");
            this.error = null; // clean error on success
            return res.json();
        })
        .catch(err => {
            this.data = null; // clean data on error
            this.error = err;
            throw err;
        })
});
```

## Rerun with Clean

To rerun and reset state:

```ts
promise.run(); // triggers async
promise.reset().run(); // resets data/error and triggers async
promise.run().stop(); // run once, then stop autorun
promise.data = null; // clean data 
promise.error = null; // clean error
```

## Disable Autorun with .finally(() => this.stop())

If you want to stop autorun after completion:

```ts
const promise = async(async function (this: Async) {
    return fetch(...).finally(() => this.stop());
});
```

## Gotchas

### Parameters Aren't Subscribed After an `await`

Reactive parameters (like signals) are only tracked up to the first `await` in your async function. If you call `id()` before an `await`, changes to `id` will trigger a rerun. If you call `id()` after an `await`, it will not be tracked for reactivity.

**Example:**

```ts
const id = signal(1);

const promise = async(async function (this: Async) {
  await someAsyncSetup();
  // This is NOT reactive:
  const currentId = id(); // Not tracked for reactivity
  // ...
});
```

**Best Practice:**
Always read reactive parameters (signals) before the first `await` if you want the async operation to rerun when they change.

```ts
const promise = async(async function (this: Async) {
  const currentId = id(); // Tracked for reactivity
  await fetch(...);
  // ...
});
```
